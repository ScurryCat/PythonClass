# 智能学习督导验收记录

验证环境为 Python 3.11、Django 5.2.18 和 MySQL 8.0.46。先迁移到 `0003_userprofile` 并导入原项目演示数据，再执行新增迁移 `0004_study_supervision`。原数据可继续使用，连续导入两次督导演示数据后仍有 3 条任务、6 条课程资料和 2 条预置提交。

| 需求 | 功能入口 | 测试及演示证据 |
| --- | --- | --- |
| R01 发布任务 | 教师督导台 → 发布任务 | 创建本课程任务后，同课程学生可见。提交其他课程或直接访问其任务接口均被拦截。 |
| R02 提交作业 | 我的学习任务 → 提交作业 | 浏览器选取模板示例图后显示预览，OCR 文本可编辑。学生提交后可回看，重复请求无法覆盖待批阅记录。自动化测试实际识别两张示例图，并拒绝无效文件、提示空白截图。 |
| R03 监督进度 | 教师督导台 → 查看进度 | 用「后台页面实践」验收统计。待批阅、已批阅和逾期各 1 人，点击统计卡后各显示 1 人，恢复全部时显示 3 人。待批阅的演示学生同时显示「迟交」。 |
| R04 批阅反馈 | 任务进度 → 批阅 | 浏览器验证无密钥时仍可手写、退回，学生可查看退回原因并重交。自动化测试验证发布反馈、模拟千问返回草稿及模拟网络故障。真实百炼调用需要配置 `DASHSCOPE_API_KEY`，本次未配置。 |
| R05 推荐资料 | 我的学习任务 → 推荐资料；后台 → 课程资料 | 输入两组识别文本，浏览器显示不同的关键词及首选资料。测试另验证了课程隔离和没有匹配资料时的空结果。 |

全站前台改版后，通过浏览器在 1440、768、390 和 320 像素宽度检查了登录、概览、基础表单和师生工作流。整页无横向溢出，宽表格可局部滚动。学生可以在手机宽度查看反馈并重交，教师可以在桌面分栏查看作业与批阅表单。评语草稿的预览、填入和失败回退使用模拟响应验证。

## 复验

在已配置的 MySQL 环境下，从 `wy_site/` 运行以下命令。

```bash
python manage.py migrate
python manage.py seed_supervision
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test courses
```

MySQL 下 41 项测试通过，其中 26 项为原项目回归测试。答辩演示路径与千问配置见 [README](../README.md#智能学习督导)。
